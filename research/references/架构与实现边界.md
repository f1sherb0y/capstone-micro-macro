## 1. 职责与状态归属

| 部分 | 职责 |
| --- | --- |
| 宏观 GBA | 环境、项目推进、业务决定校验与正式状态、聚合工程结果和事件 |
| 微观处理器 | 本机构可见信息、方法、约束、判断及内部产物 |
| 模型宿主 | 对已校验候选进行规则或 LLM 选择，按配置组织内部讨论 |
| 衔接层 | 编制场景、当前授权读取、传输决定、关联执行结果和后轮任务 |
| 结果与界面 | 展示保存的正式结果，不通过查询隐式推进世界或创建执行事实 |

实际宏观源码来自发布包解压目录，开发指南提供目标规范。当前存在必要接口修复、采购接入与独立情景付款模块，见 [修改说明](../../docs/宏观代码相对原始ZIP的修改清单.md)。

## 2. 一次动作的证据链

原请求和授权输入 → 原微观计算／判断 → 受约束决定 → 宏观校验及执行 → 同身份事件／回执 → 后轮授权读取和使用。

任务数、映射存在、内部草稿和成功提示不能代替正式执行证据。正式后果由对应宏观领域维护；衔接层不另造合同、实物或账户事实。

## 3. 当前接通范围

GOAL 1—4 已完成现有宏观入口和代表性聚合结果的接线与联调。空项目合成主链实际触发 8 类角色、40 类动作，运行至结算和后轮判断。LLM 连续案例主要覆盖 A02 报价选择，其他动作及后轮政策使用既有规则。

CASE-0005 的两项付款采用明确初值的独立本地账本，实际扣款、入账和回执进入后轮 A10；这不等于真实银行或全合同清偿。

## 4. 仍需明确的边界

- 聚合进度、质量、安全和供应状态不等于实体工作、生产、物流或独立签署核证。
- 已中选、接受或阶段归档不自动形成详细服务关系、资源独占预留、许可或完整移交。
- 宏观金额、HKD 情景解释、MOP 及实际汇率分别处理；tick、模型月和工作日不能直接替换。
- 原有恢复和防重能力按具体入口认定，未知提交先查询；补充付款阶段不称为原宏观会话恢复。
- 106／438 的契约、方法、绑定、反馈和验证逐项有证据，单案例触发数不作为总完成率。

## 5. 接口扩展原则

复用当前 `agent_module`、`decision_provider`、角色处理器、校验和事件机制。模型输出限定于合法候选和动作，不能覆盖原始投标、工程或现金事实。缺来源或正式入口时保持等待／拒绝；新增宏观能力先说明必要性和影响范围，并取得对应授权。
