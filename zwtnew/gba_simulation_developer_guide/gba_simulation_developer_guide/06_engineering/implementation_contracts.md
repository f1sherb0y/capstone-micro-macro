规范性质：目标软件架构与实现要求。实现、接口检查和研究验证分别登记证据；时间协议、资源竞争和工程模型的未定选择见 [模型决策](../07_experiments/model_decisions.md)。

[总入口](../README.md) · [研究边界](../01_overview/research_scope.md) · [共同对象](../02_world/domain_objects.md) · [项目推进](../03_projects/project_lifecycle.md) · [待定选择](../07_experiments/model_decisions.md)

本文件规定“写到什么程度才足以实现一个选定行为”，并在第 7 节维护前后端软件模块、唯一写入、查询与恢复的职责边界；公共类型和提交返回协议由[输入输出契约](interface_contracts.md)唯一维护，不另定义业务规则。实现依据本规范的领域定义，不受未登记的接口或默认值约束。角色选择仍在八份角色主文档，正式对象在 [共同对象](../02_world/domain_objects.md)，项目条件在 [项目运行](../03_projects/project_lifecycle.md)，时间及跨项目调度在 [世界运行](../02_world/world_runtime.md)，页面行为在 [前端规范](frontend.md)。对象/行为格式应填回对应唯一维护入口，并在此登记链接；不要复制出第二份相互漂移的角色规范。

## 1. 模型基准登记

| 字段 | 基础约束 | 需按场景明确的选择 |
|---|---|---|
| 地域范围 | 粤港澳大湾区内的建设、生产与合作；外部必要条件只作声明的边界输入 | 本次场景覆盖哪些地区/用途、地区规则证据与外部输入范围 |
| 主体范围 | 八类角色；每个实例独立身份/认知；每类一份主文档 | 多角色组织、项目公司、内部人员智能体依 D-03 |
| 业主目的 | 投资收益、自用需求、公共服务三类目标 | 每类目标函数和投资判断细节依 D-01 |
| 前期分工 | Owner 给目的、候选地区、规模区间、期望交期；专业及供应意见细化方案 | 第一种专业工作类型与采购模板依 D-06/07 |
| 工程覆盖 | [工程模板](../02_world/project_types.md)登记建筑（含超高层）、道路、桥梁等对象及有限方案；角色按专业任务绑定 | 首批模板、建设任务、方法适用域、数量与参数依 D-06/07；目录不代表已实现 |
| 资金范围 | 现金、应收应付、贷款、到期义务 | 账户、产品、币种、精度、利息/费用、外部执行范围依 D-02 |
| 需求范围 | 地区 × 用途指标/存量；不新建住户或使用企业智能体 | 覆盖是否包含自用需要、需求/吸纳/价格函数依 D-01/08 |
| 政府范围 | 有明确权限和证据的事项处理；内生自主调控不默认启用 | 首批地区/事项及来源，政策响应范围依 D-06/08 |
| 时间与竞争 | 必须明确版本，不由循环顺序隐含决定 | 时间粒度、同刻裁决、观察延迟、资源分配依 D-04/05 |
| 执行模式 | 真实模型、规则、离线替身分别标识，不能静默替换 | 本次模式、模型预算与验证范围依具体工作授权及 D-11 |

每个实际基准还登记 `profile_id/version`、启用的规则 ID、确认状态、地区/用途/模板、未覆盖机制及返回方式、初始化数据/参数版本。已确定选择直接使用；未确定不填一个“方便运行”的默认值。只检查本次行为真正依赖的项，不要求为实现一个账本工具先确定所有社会机制。

## 2. 共同对象字段契约

在 [共同对象](../02_world/domain_objects.md) 中为将要实现的每个对象填写下表；这里只给格式，不预定数据库技术。

| 字段要求 | 必须说明的内容 |
|---|---|
| 名称和含义 | 精确字段名、一句话含义、所属对象及正式拥有者 |
| 数据类型 | ID、枚举、布尔、金额、数量、时点、期间、引用或集合；集合是否有序/可重复 |
| 缺失语义 | 必填、可空、未知、不适用与尚未发生怎样区分；0 和 false 不作为“缺失”处理 |
| 单位和范围 | 币种、工程量、资源单位、量纲、精度/舍入、允许范围；不能从字段名猜 |
| 身份和版本 | 唯一范围、跨运行命名空间、版本不可变性、旧引用和父对象关系 |
| 时间和效力 | 发生、生效、记录、到期分别定义；边界是否包含、有效期适用时钟 |
| 数据来源 | 真实/补全/合成、证据/模型推断/情景假设，适用日期和范围 |
| 写入和读取权限 | 哪个命令/核心入口可修改，谁能读哪些投影，隐藏实际状态怎样隔离 |
| 校验与错误 | 非法单位、未知引用、陈旧版本、越权、重复或冲突的明确结果 |
| 状态性质 | 正式基础状态、派生视图、主观判断分别标注；派生值列计算来源 |

对每个状态维度另填：**当前状态 + 触发事件 + 必要条件 + 有权来源 + 对象版本 → 新状态 + 同次写集 + 事件 + 观察/后续待办**。列出拒绝、等待、不适用、技术失败和未知结果，不能只写成功箭头。

多个状态维度不得用同一个 `status` 混合，例如“编制完成、审查通过、客户接受、可用于施工”分别拥有条件。枚举名称未决定时可以继续讨论；开始编码该对象前要填实，不能任由不同模块新建同义枚举。

## 3. 角色动作开发卡

每个 A 动作的具名输入、分支输出及目标函数在对应角色文件维护，统一类型与返回协议见[类型、函数与输入输出契约](interface_contracts.md)。非角色世界/项目/政策/运行和展示函数见[系统接口目录](system_interfaces.md)，全目标入口见[函数索引](function_catalog.md)。下表是检查标准，不以填了一份通用模板代替逐动作定义。

| 项 | 填写要求 |
|---|---|
| 规则与作用范围 | 角色主文档中的 A 编号、关联规则 ID/版本、适用模板与不适用条件 |
| 触发 | 具体事件、对象/版本、时间窗口；重试、补件、撤回是否是同一业务 |
| 责任 | 发起/跟进、执行、决定、核验、接收；实际绑定槽位及授权，不只写角色名 |
| 输入 | 已定义类型的字段、可见候选、信息截止点、证据版本；缺项/不支持的返回 |
| 选择与计算边界 | 哪些值由主体选择、哪些由方法计算、哪些只是解释；普通意见与权威事实分开 |
| 结果联合类型 | 每个允许动作各有字段与约束；拒绝/等待/补件/接受互斥，不用 accepted=true 承载所有结果 |
| 进入与提交门控 | 读取条件、最终时点重验、必要接受/证据槽位；不偷读隐藏真值作全知专业判断 |
| 后果 | 新增/修改哪些正式对象；现金/资源是否真实执行；禁止改哪些字段 |
| 时间和投入 | 排队、工作量、实际投入、期间、分片、预留/占用/释放及竞争接口 |
| 失败和恢复 | 业务拒绝、技术失败、未配置、执行未知、版本冲突分别去哪里；新执行与历史核对分开 |
| 一致性 | 业务/执行/片段/回执 ID、原子写集、去重、检查点；事件投递失败不重做业务 |
| 验收和代码映射 | CHECK/fixture、具体输入与预期、新设计操作与计划入口；实现后填真实代码/测试位置 |

一个业务 A 动作可以拆成多个原子决定和例行执行，不强制“每卡调用一次 LLM”。决定本身不能修改正式余额/工程量。LLM 超时不能自动转为拒绝、默认接受或改用规则替身。

项目节点引用这些动作卡及完成条件。签约节点可以要求 Owner 和 Contractor 对同版条款分别接受，另引用必要核验证据；QS 被列入工作不代表也必须作商业接受。具体必要组合由选定模板填写，不从列表的任意/全部语义猜。

## 4. 计算方法契约

在对应共同或角色文件维护方法登记：

| 字段 | 填写内容 |
|---|---|
| 方法标识/版本与用途 | 是方案估计、实际生产、成本计算、证据生成还是指标统计；不得互相冒充 |
| 适用及不支持范围 | 专业、产品、单位、地区/模板、输入成熟度；不支持怎样返回 |
| 输入及来源 | 正式状态或可见证据、时间范围、数据/假设版本、单位、缺项规则 |
| 输出与性质 | 字段/单位/范围、估计或实际、误差或区间；结果不直接取得客户/法定接受 |
| 算法/公式 | 明确表达式与顺序、边界、零分母、上限/下限、累积/增量和舍入 |
| 随机机制 | 分布、抽样时机、独立随机流、seed/状态、重试是否复用；不因日志或遍历顺序多抽一次 |
| 参数依据 | 证据、推断、情景假设分别标记；适用性和校准状态；缺证据不捏造行业真实值 |
| 独立验收样例 | 已知输入/预期数值或性质、缺项、边界、不支持、重复执行；预期不从实现反抄 |

首个专业链要能回答：所选工程模板的方案编制方可以调整哪些方案变量；相应专业核验方按什么支持方法和证据给出哪些限定结果；QS 从哪里取得数量和价格基础；谁判断编制完成、专业通过、客户接受和用途放行。建筑空间方案与道路、桥梁等专业方案分别绑定具备对应能力和授权的 Architect 或 Engineer；编制和独立检查职能分别核对，不因同属 Engineer 角色就自动满足独立性。未具备具体方法的工作类型只能按声明支持咨询/未知/未覆盖，不能由空方法或“字段齐全”制造成功。

## 5. 初始化、实验与指标的契约标准

下表是填写标准；具体装配、运行控制、指标/网络和验证协议在 [整次运行与结果](../07_experiments/run_and_results.md)填写。期初字段与历史覆盖仍由 OBJ-021 维护，政策实验组合仍由 [政策量化](../05_policy/quantification.md) 维护。

| 范围 | 必填映射 |
|---|---|
| 初始化 | 原始列/来源 → 变换/补全方法 → 目标字段/单位 → 期初不变量；现金、初始债务、库存/产能、在建/存量、合同/参与关系分别核对 |
| 主体补足 | 缺哪个角色、为何增加、合成身份与资源来源、数量是否进入结果分母；不把补足称真实企业观测 |
| 认知基线 | 全新、复制指定基线或有意继承；run/experiment/agent 命名空间、存储与缓存键、基线来源及版本 |
| 可见信息 | 字段可见矩阵、时间截止、传播延迟、错误/纠正、私有/公开观察；全局审计视图不直接进入角色上下文 |
| 指标 | 公式、单位、样本/分母、期间、来源事件/对象、未完工/退出/失败处理、缺失规则、展示变换 |
| 运行结束 | 观察期、业务完成向量、预算/技术中断分别记录；未结事项继续存在，不为了结束画面强制结清 |
| 运行证据 | 代码及未提交差异标识、规则/配置/数据/参数版本、随机状态、决策模式/模型/预算、认知基线及结果位置 |

跨实验隔离、完全重放和保存展示快照是三种能力。外部模型、既有记忆及外部结果未冻结时，不能仅凭同 seed 声称完全复现。

## 6. 规范、配置与代码的关系

| 修改内容 | 应进入哪里 | 生效前需要什么 |
|---|---|---|
| 职责、行为含义、规则依据 | 对应 MD 主定义 | 同步依赖和验收预期；文字本身不执行 |
| 已支持的参数/白名单规则组合 | 未来结构化配置，采用明确 schema | 类型、单位、边界、引用和模板兼容校验；明确生效版本与范围 |
| 新动作、新状态或计算方法 | 代码与契约变更，同时更新主 MD | 对象/接口契约、独立测试和真实生效入口 |
| 实验后的呈现 | 结果投影及前端 | 引用已提交数据，不在 adapter 再算正式成本/进度/现金 |

每个可调配置记录：**配置字段 → 使用规则 → 读取入口 → 校验/计算/提交 → 事件或状态变化 → 指标/展示**。仅被保存或显示的字段不能标为生效；未知字段应有明确拒绝或诊断，不能静默接受后无作用。启用计算还依赖该方法的支持范围。

前端与仿真核心遵循同一领域契约。页面功能、操作及跨页交接由 [前端功能规范](frontend.md)维护；本文件第 7.4 节维护模块、状态、客户端与缓存边界。查询不隐含推进或模型调用，页面命令使用第 7.2—7.3 节的提交与恢复协议。

Skill 的接入契约见 [技能架构](skills.md)：动作/准备任务 → 技能版本 → 有权可见输入 → 工具 → 类型明确的建议/成果/决定 → 核心校验/提交 → 验收。技能可辅助主体作合法选择；其方法说明不能代替支持算法、访问控制或状态提交，也不共享不同主体的私有记忆。

MD 说明业务语义，不是任意自然语言执行器；结构化配置加载器的实现与检查证据须单独登记。配置默认仅在建立新运行时装配，既有运行保持原版本。启用运行中受控变化前，必须定义未完成任务、合同与数据的迁移规则，不能通过重载覆盖历史。

## 7. 软件实现映射

软件模块按业务规则划分。下表同时作为实现证据登记入口：没有实现或检查证据时明确标为未实现或未验证，不以计划职责冒充可调用入口。

| 目标规则/行为 | 所需正式接口与职责 | 最小验收依据 | 状态 |
|---|---|---|---|
| OBJ-011/012；Owner/Bank 资金行为 | 义务、指令、执行/核对、结算片段与事件的一致入口 | 部分执行、重复/乱序回执、未知、迟到结果与资金不足 | 目标契约；未实现 |
| FLOW-003/006/015；八类角色动作 | 按事项/范围处理的任务依赖、责任绑定及合法命令 | 多方独立接受、缺条件等待、换人、角色无权限 | 目标契约；未实现 |
| OBJ-003；主体认知 | 有限观察投影、身份与运行隔离、独立决定、记忆反馈 | 私有信息不泄露；真值、发现和主观判断分别保存 | 目标契约；未实现 |
| OBJ-006；专业和工程履约 | 有版本的方法、实际投入分片、完成量/成本和依赖变更 | 缺输入、不支持方法、部分执行、跨窗恢复不重复 | 方法细节待选择；未实现 |
| SCOPE-001—005；地区与工程范围 | 地点/路径、事项适用性、规则版本与生效事件、工程目录与方法覆盖 | 湾区范围；注册地不冒充生产地/许可；目录不等于计算支持 | 目标契约；未实现 |
| TYPE-001—008；工程模板 | profile/设计子配置、适用域、变量/单位、方法与职责依赖引用、支持证据 | 不混对象/用途/工法；父子范围不重复计量；无方法不默认成功 | [工程模板](../02_world/project_types.md)已定义目标；未实现 |
| POL-001—018；INST-001—019；政策量化 | 条款/参数来源、工具白名单、情景依赖/覆盖、稳定比较定义、有效/过渡规则与应用记录 | 宏观/原子去重、期限与实际工作分离、预算竞争、真实资金、未触发诊断、组合与单工具比较分开 | [主方案](../05_policy/quantification.md)与[工具卡](../05_policy/instrument_catalog.md)已定义目标；未实现 |
| RUN-001—019；整次运行与结果 | 数据/实例映射、期初清单、运行控制/恢复、实验作业/样本/配对、指标/网络投影和证据登记 | 期初排重、局部与全局故障、截尾/零分母、网络时间口径、比较范围/有效样本、留出数据隔离 | [运行结果](../07_experiments/run_and_results.md)已定义目标；未实现 |
| 页面操作与世界交接；CHECK-UI，见[前端规范](frontend.md) | 版本化资料/情景/运行引用、明确控制命令、同一读取上下文、对象/事件与统计投影 | 只读不推进、创建不冒充完成、历史不混当前、零/未知/示例分开、实际比较可追溯 | [前端规范](frontend.md)已定义目标；未实现 |
| 前端模块与上下文；本节7.4及CHECK-UI，见[前端规范](frontend.md) | 页面用例、共享引用/查询上下文、局部选择、类型化读写客户端、纯展示适配与隔离演示入口 | 跨页身份一致、请求竞态与缓存隔离、未知不补值、组件不直接改正式状态 | 目标重构契约；未实现 |
| 政策实验与比较呈现；[政策量化](../05_policy/quantification.md)/[运行结果](../07_experiments/run_and_results.md)及CHECK-UI，见[前端规范](frontend.md) | 完整ComparisonContext、实际run集合/配对、服务端比较结果、局部MapViewSelection与版本式导出 | 切换一对run不改总体统计；指标/窗口/范围一致；缺配对与未完结果可追查 | 目标重构契约；未实现 |

实施时每行补规则版本、类型/动作、状态拥有者、调用方与被调用方、提交入口、配置作用点、目标代码和测试位置、实际验证日期与证据。跨模块使用同一对象身份和正式事实，不在前端或角色私有状态中维护另一份正式账本。

### 7.1 软件组织与唯一写入归属

软件架构采用**模块化单体**：同一运行的领域模块在同进程协作，运行状态使用支持本地事务的一套持久状态库；不按八类角色拆成八个服务。数据库产品、时间精度、资源竞争算法和工程计算方法分别按实现选择与模型决策登记确定，不能由软件模块划分隐含指定。研究数据、模型网关和外部执行适配器可独立存在，但不能直接改运行账本。

| 模块 | 唯一维护的状态/记录 | 允许依赖与输出 |
|---|---|---|
| 运行编排 | 运行清单、控制状态、调度位置、待办与技术预算 | 按 [世界运行](../02_world/world_runtime.md) 的已选协议分派任务；提交正式控制变化；不替主体投资、接单或批准 |
| 环境与需求 | 环境路径、地区用途需求/存量、实际吸纳及作用记录 | 读取正式交付/使用与场景输入；输出环境/需求变化，不把预测当交易 |
| 业务关系 | 合同条款/接受槽位、委任、参与关系、职责绑定 | 输出有效承诺与范围；债务和资源变化通过对应领域准备，不直接改其账本 |
| 项目与工作 | 机会/投资案件、项目范围、工作包/任务依赖、成果版本和用途状态 | 调用领域只读条件检查，输出任务和成果变化；不自行生成专业通过或现金 |
| 工程与实物 | 实际执行分片、数量/质量/物理位置、库存、容量承诺与实际占用 | 使用已登记计算方法，准备资源与工程变化；不因语言建议增加产出 |
| 资金与清偿 | 现金、应收应付、贷款/义务、指令、执行/结算片段及归集 | 读取有效合同、核证和结果证据，维护同一义务；到期列表只作其派生视图 |
| 事项与制度 | 事项案件、许可/监管记录、政策规则版本、适用和生效记录 | 按实际有权来源及模板准备变化；环境效果、资金支付分别交其拥有模块 |
| 主体决策 | 实例身份、私有认知、请求/返回、显式决定、技能任务进度 | 只读本主体授权投影；输出类型明确的命令/材料，不保存另一套正式资源 |
| 提交与投递 | 提交序列、命令回执、事件、待投递与消费身份、持久恢复位置 | 协调上述拥有者的合法写集并存储；不新增业务放行条件或替主体选择 |
| 结果投影 | 服务端指标、网络、审计、正式差值/统计与界面的派生结果 | 只读已提交事实；依据[政策量化](../05_policy/quantification.md)/[运行结果](../07_experiments/run_and_results.md)的比较定义维护结果版本，不反写基础状态或成为角色全知上下文；前端不另算一套 |

每个具体对象类型登记唯一拥有模块和允许命令；跨表引用同一对象身份。表中分组是软件职责，不新增角色或业务授权。私有认知由主体模块定义变化，统一持久化并不允许其他主体读取。正式状态的业务拥有者与负责落盘的提交模块不是两套写入权。

[工程模板](../02_world/project_types.md) 的工程模板作为有版本的配置与方法引用装配，不另建一套工程状态服务。项目与工作模块维护 [共同对象](../02_world/domain_objects.md) 的范围层级、模板绑定和 [项目运行](../03_projects/project_lifecycle.md) 的任务依赖；工程与实物模块按匹配方法计算，资金模块维护唯一收付与义务，结果投影按 [运行结果](../07_experiments/run_and_results.md) 汇总。模板修改需重新核对受影响输入／任务／方法的兼容性，不能仅修改 MD 或目录枚举就声称新工程已可运行。

依赖方向固定为：适配/决策或调度入口 → 应用用例协调 → 领域的查询/准备函数 → 提交存储；结果投影和观察读取已提交输出。领域模块不能调用 LLM、触发调度循环或直接调用另一领域的写入口；跨域读取使用声明的只读接口，跨域写由一个用例收集各拥有者的类型化变化。工程计算只依赖显式输入/方法，返回结果，不持有可任意修改的世界对象。

容量冲击可使旧合法承诺超过当前有效能力；保留合同与短缺，实际使用受有效容量约束，新承诺按当前可承诺量校验，不删除既有义务来修平。

候选筛选、流程就绪和最终提交复用领域条件检查；前两者的结果仅对各自输入版本有效。调度器执行已选的竞争协议，领域提交仍复核当前条件。软件 `commit_seq` 的顺序不得被倒用作未声明的商业优先规则。

复用规则实现不代表共用输入可见范围或全部门控。候选筛选按该阶段获授权的可见证据处理，未知资格保留未知；正式动作再按其硬条件核验。不得用提交端掌握的隐藏质量或未来结果预先排除主体候选，具体可见性沿 OBJ-003。

### 7.2 命令身份与一致提交

每个运行只有一个活动提交协调者，工作区也有自己的提交空间和写入代次；并行准备不等于并行任意写入。协调者以持久的写入代次 `writer_epoch` 阻止恢复前的旧执行者继续提交。每次成功持久化运行状态批次取得递增 `commit_seq`，技术记录批次也可有序号，但不因此生成业务事件或推进模型时间。

命令信封、稳定调用身份、领域排重、准备/提交/回执、外部未知及错误返回统一引用[公共接口协议 第5节](interface_contracts.md#5-命令准备提交与回执)。本节只规定哪些模块在何处执行该协议，不复制字段或建立第二套结果状态。

一次处理按以下顺序执行，所有正式入口，包括规则主体、LLM/Skill、例行履约及初始化，均遵守拥有者和提交边界：

1. 宿主持久登记待办、请求和必要版本，执行有权限的读取/模型/计算并保存要采用的返回及来源；长调用不占数据库事务。主体决定只是候选，工具算完也未证明已提交。
2. 编排层依已选时间/竞争协议确定可处理命令。各领域检查权限、输入与当前版本，并准备各自变化；纯计算可在事务外完成，提交时仍须核对其依赖版本。不得由准备完成或网络返回的先后抢占业务优先权。
3. 在一个短事务内核对写入代次、命令身份与依赖版本，完成最终条件检查，并一致保存本次写集、命令回执/业务排重、因果事件、后续待办及待投递记录。明确需要同时成立的跨域条件失败时不留下部分有效状态；可保存拒绝诊断。提交成功后才返回成功回执。
4. 提交后分别分派例行执行、投递观察、更新投影。通知或界面失败只重做对应消费，不能重新扣款或完成工作。提交响应丢失时先按原 `command_id` 查询；无法确认则保留待核，不换身份重新执行。

上述原子边界是一次已定义的业务变化，**不是整个项目、整期或所有合同流程**。合同先成立、后分期付款、分批交货、分次接受可以是多个合法提交；以每个动作的必要同时条件为准。不可逆或外部执行先持久登记授权/尝试，再在事务外派发；结果按原身份核对。适配器不能保证外部去重时，超时进入未知并核对，不自动重发或声称对外“恰好执行一次”。

新承诺/新执行入口按当前门控校验；已发生结果入口依 OBJ-012 核对原执行、发生时点、范围、证据和唯一片段。合同关闭或现权限变化不丢弃可信历史事实；超额/越权事实记录异常，不补发授权。这里分离入口，不以统一事务方案把两种校验混成一套。

### 7.3 观察消费、随机记录与恢复位置

正式事件和待投递记录在同次提交保存。投递项以 `(run_id, event_id, recipient_id, projection_version)` 标识，包含按 [世界运行](../02_world/world_runtime.md)/[共同对象](../02_world/domain_objects.md) 确定的可见范围和可交付时点；重试不改变原证据，也不把迟到信息补入过去上下文。纠正信息形成关联的新事件，不能覆写已消费记录。后续工作是否需要模型时间仍由业务方法决定。

投递可以至少一次重试，**认知效果按投递身份最多记入一次**：主体按可见次序读取；若需模型解释，在事务外准备并登记采用的输出；提交时核对认知版本，将观察内容、认知变化、已消费身份和相应待办一起保存。消费游标辅助定位，不能仅凭全局最大事件号跳过尚未到可见时间的项。解释失败可先保留已收到的原始观察及待解释任务；后续解释另用稳定任务身份，不伪造已学到内容。认知版本冲突保留待处理项，不能把旧上下文结果直接覆盖新状态。

内部随机计算使用有版本的方法及稳定抽样身份 `(run_id, stream_id, execution_scope_id, draw_key)`；重试复用该身份的已登记结果，或按固定算法/输入重现同值。抽样结果和所用算法/输入摘要随正式变化保存；同身份不同输入报冲突。技术日志、模型响应顺序或重复投递不能额外推进业务随机流。具体分布、相关结构和需要抽样的时点由方法/profile 定义，此协议不替选。

权威恢复源为持久运行状态库，而非界面快照。检查点取得同一已提交序列 `C` 的一致视图，覆盖 [运行结果](../07_experiments/run_and_results.md) 所列正式对象、队列/待办、观察和认知、请求/命令/未决执行、随机记录及运行清单；同时记录调度位置与输入/方法/技能内容身份。可使用存储一致快照或短提交屏障取得它，不能逐模块复制不同时间的当前值后称为完整检查点。

续办取得新的写入代次，先确认最后持久序列与调度位置，再续办未消费投递和未完成任务；已提交命令返回原回执。未决外部结果先核对，独立事项按原隔离规则继续。若只有旧检查点、却缺少其后可能已执行的记录，标出恢复缺口并核对，不能直接回退重付；新的参数/Skill/方法运行依 [运行结果](../07_experiments/run_and_results.md) 形成分支。持久事件用于追溯与投递，不要求仅凭事件重建全部状态的完整事件溯源实现。

模型装配固定动作契约、schema、方法、工具、Skill/提示的版本及内容摘要，并检查显式兼容关系；版本名相同但内容改变不能默认为同一程序。缺支持能力只阻止依赖它的入口，不添加用户审批，也不把业务上可发生的无候选、拒绝或资源不足当成装配错误。

### 7.4 前端模块、上下文与服务边界

前端是同一系统的操作与呈现端，按 [前端规范](frontend.md)落实资料、装配、运行、观察与比较。以下为目标模块职责，实际目录命名可据实现组织；不预定状态库、查询库或图表框架。页面功能和交互由 [前端规范](frontend.md) 定义，模块按明确状态归属组织；不以单一页面文件承担全部业务状态。

#### 模块和状态所有者

| 模块 | 唯一维护的前端状态/职责 | 允许依赖与限制 |
|---|---|---|
| 应用外壳 `app shell` | 导航、布局、全局运行/查看位置提示、错误边界与模式入口 | 装配页面和共享上下文；不持有企业账本、政策计算或每页图表算法 |
| 业务页面 `features` | Agent/Cluster、Policy、Workflow、Simulation、Analytics、Reports、Setting/Overview各自的用例、草案编辑与请求状态 | 依[前端规范](frontend.md)组合查询和命令；通过显式交接传身份，不直接改另一个页面的私有状态 |
| 共享上下文 | 资料/草案、实验/运行身份、ComparisonContext、QueryContext及模式切换 | 集中维护当前引用和切换动作；持有只读快照缓存不等于成为正式对象拥有者 |
| 页面局部上下文 `view-local` | 折叠、排序、搜索输入、地图视角、图层、选中对象和MapViewSelection | 使用共享引用，默认不改实验定义/实际run集合；局部明细查询另带选择身份 |
| 查询客户端与缓存 | 类型化查询、取消/去重、读取令牌、缓存水位和可用性 | 只读；不隐含创建运行、推进时间、模型调用或写认知；昂贵结果生成另走命令 |
| 命令客户端 | 用户操作请求身份、预期版本、回执、未决状态及核对 | 调用有权应用入口；取消界面等待不等于取消业务，不将HTTP成功映射为业务全部完成 |
| 展示adapter | DTO到视图模型的纯映射、标签、格式/舍入、图形几何和已声明显示变换 | 保留原值/单位/版本/缺失性质；不请求网络、不改世界、不填示例事实、不计算正式指标或效果差值 |
| 共享呈现组件 | map、inspector、timeline、compare及基本表格/图形 | 接收有类型的数据和上下文，发出选择/查看/控制意图；由页面处理，不自行调用正式命令或查隐藏状态 |
| 隔离demo数据 | 显式演示模式的fixtures、模拟回执与来源标记 | 使用独立命名空间/传输入口；接口错误不自动切demo，demo对象不通过真实命令客户端提交 |

依赖方向为：外壳装配上下文与页面；页面用例调用读写客户端并将结果经adapter交给组件。组件发出的意图返回页面处理，不能由地图点击、图表订阅或adapter悄悄启动仿真。正式合同、资金、资源、工程、主体认知及指标仍归第7.1节服务端拥有者；前端最多缓存其带版本投影。基础校验可在表单提供即时反馈，最终适用性和提交条件仍由服务端核验。

#### 完整共享上下文与局部比较选择

共享模式显式区分资料、草案、运行、比较和demo；适用字段使用类型化分支，不能给未选择运行的资料页塞一个虚构run_id。`RunContext`保留run_id、manifest引用、服务端运行状态与世界最新处理位置；`QueryContext`另保留当前读取快照/令牌、实际业务时点、各返回水位和信息视角。运行执行状态、分析结果可用性和界面读取状态为三个独立轴，不能用一个loading/completed标志相互推断。历史查看位置不覆盖世界最新位置；研究者审计视角与某主体当时可见视角采用不同访问范围。

`ComparisonContext`是[政策量化](../05_policy/quantification.md)/[运行结果](../07_experiments/run_and_results.md)正式比较定义的跨页引用载体，不在浏览器重新定义统计。其具名字段以[系统接口的ComparisonContext](system_interfaces.md#121-查询与导出类型)为唯一技术定义；下表仅解释前端持有职责。未建立比较时标未配置，结果未生成时标待生成，不虚构ID或数值。

| 上下文组 | 必须携带或可由固定版本引用完整解析的内容 |
|---|---|
| 研究与方案 | `portfolio_id/version`、`contrast_id/version`、各比较位置对应的`scenario_id/version`；S0/S1等仅作展示名 |
| 实验执行 | `experiment_id/version`、对应`execution_job_id`引用与状态、`run_set_id/version`及实际run成员/情景归属；保留计划、已完成、失败/未完与未加入的区别 |
| 配对与结果 | 适用时的`pairing_id/version`及实际成员配对、缺配对原因；`comparison_result_id/version`及状态、所依据的run集合/配对版本，不从相同seed或数组位置猜配对 |
| 业务时间窗口 | 时点或区间、两端包含规则、模型时间单位/历法、跨run对齐依据；统计窗口与界面播放速度无关 |
| 指标和单位 | `metric_id/version`、单位/币种、统计口径与结果版本；涉及换算时附服务端采用的方法/版本，不把同名不同单位视为可比 |
| 对象与地域范围 | 对象类型/层级、项目/子范围或其他研究集合及版本、地区范围与归属口径、过滤/纳入排除定义；不能以地图当前可见点替代样本 |

方案/对比的业务定义归 [政策量化](../05_policy/quantification.md)，实际run集合、配对、差值/统计、缺失处理及结果发布归 [运行结果](../07_experiments/run_and_results.md)。服务端返回可解析的固定引用或清单及上下文摘要；大集合可以分页，但须有不随翻页变化的集合版本。无法对齐窗口、单位或样本时返回不可比及原因，不计算貌似完整的差值。

`MapViewSelection`只保存本地查看的A/B实际run、侧别/视角、图层、选中对象和缩放等；所选run须属于可查的正式比较范围，是否为有效配对从pairing读取。查看一对run不缩减原run_set、不改配对总体，也不使总体均值/差值换成这一对结果。界面同时标明“当前查看这一对”与“总体比较”。若用户有意改变正式情景、对比、成员范围、指标或业务窗口，由页面用例请求有版本的新配置/结果并替换ComparisonContext，不能仅改局部下拉状态后继续沿用旧统计标签。

#### 读写隔离、竞态与不可用状态

查询缓存键至少由模式/数据来源、访问视角与授权范围、查询类型/schema版本、对象身份及版本、run/一致读取令牌、规范化筛选/分页参数组成；比较查询还包含完整ComparisonContext的版本/摘要，局部配对明细另含MapViewSelection中影响该明细的字段。没有参与结果的纯显示状态不扩张业务查询键；名称和全局当前tick不能替代上述身份。缓存命中不扩大访问权限。深链接仅携带允许公开的对象引用和查看参数，不嵌入私有认知、凭据或授权令牌；打开后按当前权限重新读取。

切换运行、比较版本或查看快照时，递增当前请求代次，取消可取消的旧读取/订阅；响应只有在代次与请求上下文仍匹配时才能更新当前面板。单次请求取消不了远端工作也无妨，迟到结果不得覆盖新上下文。水位单调检查仅用于同一身份/查询语义的最新视图；用户明确回看较早快照是合法切换，不能被“禁止版本回退”拦住。

同屏需要一致的地图/对象/资金/比较面板共用读取令牌或服务端发布的结果版本；只能提供最终一致时分别标水位与过期范围，不假装是同一时点。订阅或轮询只刷新已提交投影，断线重连不补执行命令。原始快照、view model和加载/错误状态分层，保留旧值时必须显示其实际时点及过期状态，不能继续标为最新。

读取结果分别表达未请求、加载、有效空集合、有效零值、未知/缺失、不适用、未支持、访问受限、技术失败和过期；业务等待/失败读取对应正式状态，不与网络错误合并。组件能表现这些状态，adapter不得把它们都转为0、false、空数组或示例成功。比较缺一侧、run未完或结果未发布时显示覆盖与不可用原因，不能补造基准曲线。

命令按第7.2节和[前端规范](frontend.md)的回执边界处理：首次派发前确定稳定请求身份与预期版本；重复点击/技术重试查询同一结果，未知不换ID重发。草案保存可以展示未保存编辑，但正式状态不作“已执行”的乐观回填。浏览器关闭/取消请求不宣布业务回滚；再次打开按请求/任务身份核对。演示与真实环境使用不同客户端入口和缓存命名空间，导出同样保留demo性质。

#### 服务端比较、版本式导出与贯通验收

正式指标、单位/币种换算、差值、交互量、统计分布/区间、网络聚合和比较结论所用的数值，由结果服务按[政策量化](../05_policy/quantification.md)/[运行结果](../07_experiments/run_and_results.md)定义计算并发布结果版本。前端compare组件可改变排列、颜色、对齐展示和显示精度，但不从当前选中两条曲线临时计算一份“政策效果”，也不按图层可见节点重算正式分母。纯展示变换保留方法和原值引用；改变分析含义的筛选向服务端请求相应范围结果。

导出命令固定草案/运行/ComparisonContext、实际run集合/配对、业务时间、metric/统计版本、对象地区范围和结果版本；报告级汇总与局部A/B截图分别声明范围。生成任务返回`export_job_id`及固定请求摘要，完成后返回所用版本、文件清单和生成状态。生成期间用户切换运行或筛选不会改变该任务；迟到事实形成新统计/新导出版本，不能覆盖已交付旧包。缺项、未完、示例与不可比状态一并进入导出，不把导出成功当成仿真完成或研究验证。

前后端按同一端到端用例分阶段实现。业务机制的就绪依赖见 [运行结果 第 9 节](../07_experiments/run_and_results.md)，页面功能验收入口见 [前端规范 第 10—11 节](frontend.md)。下表只维护技术集成阶段；模型未选部分按支持范围留缺口，不由联调 fixture 替选。

| 贯通阶段 | 交付的可检查连接 | 最小验收与限制 |
|---|---|---|
| 1 只读上下文 | 版本化查询→缓存/adapter→地图、对象与认知面板 | 同run/快照一致、切换后的迟到响应不覆盖、零/未知分开；可用隔离fixture，不冒充真实运行 |

## 8. 确定状态验收样例

以下复用 OBJ-011 的示意数据；单位虚构、同币种、无费用/代扣，不是产品或行业参数，也不替代完整项目场景。首次实现时再绑定实际字段和命令。

| 顺序/事实 | 业主现金变化与余额 | 服务义务未清 | 贷款本金 | 关键核对 |
|---|---|---|---|---|
| 初始现金 100，已成立顾问费 20 | 余额 100 | 20 | 0 | 明确初始来源；双方引用同一义务 |
| 银行批准 50，但尚未执行 | 变化 0，余额 100 | 20 | 0 | 批准不是到账或债务 |
| 有效支付并确认顾问费 8 | 变化 -8，余额 92 | 12 | 0 | 顾问现金 +8；片段、清偿和占用一次提交 |
| 实际到账贷款 30 | 变化 +30，余额 122 | 12 | 30 | 模型内资金方相应 -30，或有明确外部边界记录；不得凭空造钱 |
| 重放上述付款和到账回执 | 变化 0，余额 122 | 12 | 30 | 可恢复通知，不能再变余额 |

另设独立分片例子：批准执行 100，先确认 60、余下 40 未知；后来同一执行累计确认 100，只增加 40。分别覆盖重复/乱序回执、未知时重试、换人后迟到结果、记账中失败、记账成功而通知失败。两组例子不拼成一套未声明的产品流程。

每个正式 fixture 保存初始对象与版本、启用规则/方法、命令和事件次序、每次成功后的余额/资源/工程状态、预期错误、禁止发生的副作用及恢复后的结果。全项目 fixture 覆盖该工程模板实际需要的主体输入/输出连接、资源不足、拒绝/无候选、版本变化、等待和观察期截止；整套基准集合检查八类角色，不强制每个道路或桥梁项目都出现全部角色。由离线替身固定选择只能验证工程链，不能证明真实模型会作相同选择。

以下补充第 7 节的待执行软件验收，不使用新的业务规则编号：

| 条件/中断点 | 必须观察到的结果 |
|---|---|
| 某动作明确要求合同、义务、资源同时成立；新增资源承诺最终校验失败 | 三者均不形成部分有效结果；已有其他合同/义务不回滚。另一个允许先签约后排资源的模板按自身条件执行 |
| 同命令重试；同 ID 换内容；不同 ID 重复同一结算片段 | 分别返回原结果、身份冲突、原片段/重复诊断；现金和库存均只改变一次 |
| 业务提交前；提交后通知前；认知变化与消费身份保存后分别中断 | 固定离线决定下，恢复的正式状态、认知与待办等于不中断运行；通知可重发，业务和学习不重复 |
| 一次外部执行结果未知；其他不相关项目有可执行任务 | 未知范围保留占用并先核对，其他合法工作继续；不能改 ID 重付，也不能全局静默停机 |
| 从同一检查点续办，旧写入者同时迟到；交换模型返回顺序 | 旧代写入被拒；所选时间/竞争协议结果不变；若需抽签则用相同抽样身份，不靠提交序号制造赢家 |
| Skill 的内部命令已提交，最终返回丢失或失败 | 按 [技能架构](skills.md) 声明的调用模式核对原命令/子命令；已提交事实保留，最终输出不能再次产生同一副作用 |

## 9. 编码就绪条件

该闭环有明确适用模板；所有输入、输出、状态/动作和单位均有定义；每项必要决定/证据落实到槽位与实例；其计算有支持方法和独立预期；资金/资源与失败恢复不变量明确；新设计的调用、输入输出和状态拥有者明确。未覆盖路径有具体返回而非默认成功。

达到这些条件后，该闭环具备编码所需的规范依据。未决外围选择不阻止与之独立的实现；涉及模型范围或业务权限的改变仍须落实相应决策。完成代码后才填“已实现”，实际检查完成后才填对应“已验证”；文档自洽、离线测试、真实模型表现、参数校准和政策效应验证分别记录。
