## 1. 验证层次

| 层次 | 回答的问题 | 必要证据 | 不足以替代的证据 |
|---|---|---|---|
| 文档一致性 | 规则是否唯一、依赖明确、字段及异常可解释 | 链接/编号/字段检查、交接审阅、方法缺口登记 | 文件多、篇幅长、术语齐全 |
| 软件正确性 | 程序是否按已选规则执行 | 行为和失败路径测试、状态不变量、接口契约、恢复/幂等检查 | 普通成功路径通过、HTTP成功、日志存在 |
| 界面与服务一致性 | 操作和展示是否对应真实状态与范围 | 浏览器交互、读写隔离、查询竞态、历史/比较/导出核对 | 构建成功、离线示例看起来正常 |
| 工程与资金方法 | 方法在其适用范围是否计算正确 | 独立手算/基准、单位守恒、极值、已知案例及来源 | LLM给出合理文字、有限参数下没有报错 |
| 行为与机制 | 决策或反馈能否解释目标现象 | 简单基线、可见信息控制、反例、消融、暴露/选择/执行分解 | 更多对话、更长记忆、预设评分上升 |
| 参数校准 | 参数如何由资料约束、是否可区分 | 数据用途登记、拟合目标、误差、相容参数族与敏感性 | 用模拟自己的输出验证自己的参数 |
| 独立研究验证 | 模型能否解释未用于调参的资料 | 项目/时间/地区等适当留出、替代模型、预测误差与不确定性 | 样本内拟合、单次最优情景 |
| 政策因果主张 | 现实变化能否归因于某项政策 | 与主张相符的识别设计、数据和假设检查 | 模拟组间差值、显著地图、置信区间本身 |

规范组织参考 [ODD 方法](https://www.jasss.org/23/2/7.html) 对目的、实体、状态、时序、初始化、输入和子模型的分解；验证层次参考 [Sargent 的仿真验证与确认框架](https://www.informs-sim.org/wsc04papers/004.pdf)。这些是方法依据，不提供湾区政策阈值、工程参数或本平台有效性的证明。

CHECK编号继续随其业务定义维护；实现代码通过这些编号登记测试证据。本文件负责跨模块检查策略，不重复复制全部CHECK表，也不依据一次测试把整份规范标为验证通过。

接口验收以成对生产和消费为单位：检查上游成功/拒绝/缺项输出能否被下游按同一schema、版本、范围和单位处理；对重复、越权、陈旧版本、提交响应丢失保留确定预期。目标函数目录完整不等于现有源码已逐函数映射，源码扫描绑定和运行测试分别登记。文档检查不执行业务验收例，也不能证明数值方法正确。

## 3. 完整世界的贯通检查

为选定模型建立至少两个项目竞争共享资源、跨两个经营周期的隔离基准。数据可以是明确标注的合成输入，但必须有独立可核对预期；不要求一个样例穷举全部地区和工程类型。F-GBA-01只覆盖指定局部接线，完整经营基准还需满足下表。

| 情形 | 应核对的结果 |
|---|---|
| 无新增政策运行 | 在既有制度、有限需求/载体/资金下形成或放弃机会；交付和经营结果进入下一周期，主体不重置 |
| 两项目争共同资源 | 一份人员、工厂、资金或通道能力不因项目数翻倍；等待、调整和退出有依据 |
| 拒贷、零投标、资金不足 | 明确业务阻塞和有权主体的下一选择；独立业务继续，不自动生成企业、融资或许可 |
| 共同通道关闭/资源损伤 | 按共享物理身份影响所有暴露对象；程度由暴露和替代决定，无关项目不无条件暂停 |
| 工程、质量与返工 | 实际投入产生限定产出；真值、检查发现、接受和责任分开；返工不凭空提高可用量 |
| 交付、交易及继续经营 | 资产、可用服务、需求满足、权利、应收应付与现金分别更新；保留债务和背景负荷 |
| 政策生效但执行不足 | 规则可有效而申请/服务仍排队，预算可耗尽；能定位资格、信息、资源、资金或独立选择的作用 |
| 响应顺序/线程改变 | 相同业务输入和竞争规则下不增加技术先后带来的商业优势；中断恢复不重复履约 |
| 开放/限制跨区合作 | 记录候选、资格、成本、任务与履约变化；不偷偷改变需求规模、质量或比较总体 |
| 历史、地图及分析联动 | 同一查询上下文可回到正式事件；选看一对运行不改变分析全集，浏览未来不推进世界 |

所有情形允许合理的失败、未完和不合作结果。验收检验规则是否正确执行，不以“全部成交/全部完工/政策有利”为成功标准。

## 4. 高风险实现边界

1. **状态所有权**：正式工程、资金、资源和合同各有唯一维护者；页面、Skill和私有认知不能各维护一套事实。跨域条件需同时成立时一致提交，部分合法履约使用明确分片。
2. **未知与恢复**：提交前、提交后通知前、观察消费前后分别注入失败；核对回执、账本、队列及认知不重复。外部执行未知不换身份重发；展示快照不等于完整检查点。
3. **项目存续**：拒绝/重招/换人时释放或保留资源须有依据；项目终止后仍保留债务、缺陷及其他责任。资源冲突后的新校验与同命令技术重试分开，接口准备见W5。
4. **范围与数量**：总项目、区段、工作包、产品和物理资产身份一致；父子汇总不双计，共享来源不按项目复制。世界覆盖和背景业务须满足W1，共同运输容量见W2。
5. **跨组织承诺**：一方选择不替对方接受；联合体成员权力、资源和责任不自动转移；资产转手不抹去存续合同和债务。相关能力依W3/W4填实。
6. **行为解释**：资格、可见候选、实际邀请、响应、接受和履约分别记录。模型调用少、未曝光或技术失败不能解释为主体拒绝；地区标签不能直接变成能力或偏好结论。
7. **结果解释**：失败、未完、样本覆盖和不确定性进入结果；观察窗口、单位、分母、配对依据及方法版本一致。单工具效应需要相应比较，不能分摊政策包总收益。

W项的适用条件、关闭标准及主文档落点见[模型决策与实现准备](model_decisions.md)。确认缺项后填回拥有规则的文件，避免同时维护问题清单与另一套正式规则。

## 5. 研究机制的可辨识性

| 主张类型 | 必须能区分的竞争解释 | 建议观察与对照 |
|---|---|---|
| 准入扩大缓解瓶颈 | 只是订单从本地转给外地，总交付未增加 | 资格、曝光、容量占用与总完成；只改资格/只改信息/组合；能力宽松对照 |
| 候选服务促进合作 | 名称/顺序偏差、更多模型调用或更长候选列表 | 实际展示集合、排序截断、等价名称扰动及相同决策预算 |
| 学习改善选择 | 只是输入信息更多，或评价资料已用于调参 | 固定记忆与指定更新、相同可见信息、独立任务上的预测与选择质量 |
| 生产集中降低成本 | 工业化方法本身、规模、订单集中或空间迁移混在一起 | 分开技术方式、地区内组织重排、跨地区合作；计入运输/适配/协调/闲置和扩产代价 |
| 政策组合有协同 | 加了执行能力/预算，或有效样本与总体不同 | 合法0/A/B/AB或条件比较、投入差异、有效运行及估计量，区分交互正负与好坏 |
| 模型解释长期区域变化 | 固定外生价格/需求已包含结果，遗漏企业进入退出 | 反馈范围、备选结构、时滞、未覆盖通道和结构敏感性 |

每项主张登记可以使其不成立的条件、简单基线、备选机制及独立观察。不能区分的参数族保留多种相容设定并报告预测差异，不任挑一组称为现实真值。重复随机运行、参数敏感性和模型结构比较分别报告；同seed不保证外部模型完全复现。

## 6. 执行与交付记录

每项验证记录至少包括：检查身份及规则引用、所检配置/schema/方法与代码版本、数据来源/隔离目录、真实模型或规则/离线替身模式、随机与认知初态、预算、预期与实际结果、失败/未执行理由、复现入口和证据文件。测试用的简化方法不替选生产模型。

| 阶段 | 进入条件 | 交付条件 |
|---|---|---|
| 契约与合成基准 | 身份、单位、状态和失败语义明确 | 不变量和手算预期一致，缺方法/未知保持可见 |
| 单次世界闭环 | 启用机制的方法及模型选择就绪 | 数据装配、主体决定、正式执行、反馈和控制可追踪 |
| 前后端集成 | 对应命令/查询与结果来源可用 | 契约检查、构建/类型检查及浏览器交互分别记录；无隐藏推进或示例回填 |
| 政策比较 | 合法比较定义、实际运行计划与授权预算 | 样本/配对/失败/未完透明，地图分析导出同口径，机制路径可钻取 |
| 研究结论 | 校准、独立验证、替代模型及识别条件充分 | 主张与证据强度一致，适用范围和未覆盖机制明确 |

没有已执行证据的项标为待验证；未实现项不假装测试失败，缺数据与技术故障也分别登记。已有实现的测试通过不自动证明符合全部新规范；需要按规则映射检查具体能力。
