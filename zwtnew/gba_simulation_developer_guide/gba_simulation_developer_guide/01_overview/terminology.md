## 1. 研究与业务层级

| 术语 | 含义 | 必须区分 |
|---|---|---|
| 世界 | 一次运行中声明的地区、主体、资源、规则、建设与经营活动 | 世界是模型边界，不等于完整现实社会 |
| 组织 | 有稳定身份的企业或机构，可有多个经营/履职单元 | 来源记录、组织实体和运行实例不互换 |
| 角色 | Owner等行为模板 | 角色名称不授予实际资格或项目权限 |
| 职能与授权 | 某主体在特定事项/范围内可以执行或决定什么 | 发起、执行、决定、核验和接收可由不同主体承担 |
| 智能体 | 运行中的独立组织决策实例，拥有自己的可见信息和认知 | 不是开发助手；不因共用模型网关而共用记忆 |
| 机会/提案 | 需要、候选地点、规模及有限研究的记录 | 不等于正式项目、排他权、融资或许可 |
| 项目 | 按有效条件登记的建设安排与责任范围 | 总项目、子工程、区段和工作包不能重复计数 |
| 工作包/业务任务 WorkTask | 有范围、输入、资源、完成标准和责任的实际工作，可归组织、前期档案或项目 | 工作请求、授权、任务创建和实际执行分开；完成不等于已获全部批准 |
| 决策调用任务 DecisionTask | 宿主登记的一次主体行为请求，绑定动作、可见上下文和允许输出 | 不要求待申请的业务工作已经存在，也不授予履约、支付或签约权限 |
| 成果 | 方案、专业意见、数量、证据或其他交付内容 | 编制、核验、客户接受、法定决定与用途发布分开 |
| 建造方式 | 工程模板内可选的组织/技术方式 | 工程对象、用途、超高层特征和业主目标是不同维度 |
| 跨区域合作 | 按指定组织来源、履约地点、工程范围及制度边界定义的关系 | 注册地差异、实体跨区、服务跨区和制度事项不能合成同一指标 |

## 2. 决策与正式事实

| 术语 | 含义与责任 |
|---|---|
| Observation 观察 | 已按权限与时点送达的事实或材料，包含来源与可见范围 |
| Proposal 建议 | 主体或方法提出的意见/候选，不自动授权或提交状态 |
| Decision 决定 | 有权主体在允许动作/候选内作出的选择，仍需合法性检查 |
| Command 命令 | 带身份、版本、对象及依据的正式执行请求 |
| Committed Event 已提交事件 | 核心校验并提交后的事实，可用于结果、后续任务和观察投递 |
| 技术回执 | 请求的受理、提交、拒绝、失败或未知状态；成功HTTP不能替代业务完成 |
| 例行执行 | 根据已有授权和明确方法执行的工作，不要求每一微步重新调用决策模型 |
| 认知 | 某主体的记忆、判断、预期和意图；可有误，不覆盖正式世界事实 |
| Skill 技能 | 有输入、工具和输出契约的可复用能力；决定与副作用遵循宿主提交边界 |

一条链可以不需要建议，也可以先完成例行计算再形成观察。只记录实际发生的环节，不能为了凑齐流程补造Proposal或决定。

## 3. 资金、资源与结束状态

| 容易混用的词 | 正确边界 |
|---|---|
| 预算、承诺、应付、现金 | 可支出边界、有效承诺、到期/未清义务与已执行资金分别记录 |
| 授信、提款和债务 | 可用融资安排不等于现金；按真实执行及产品方法形成余额与到期义务 |
| 报价、成本估计和实际成本 | 意向价格、方法预估、实际投入/结算按来源和范围区分 |
| 可用、预留、承诺、占用与释放 | 同一资源的不同约束状态，共享容量不按项目复制 |
| 制造完成、发运、到达与接收 | 不同物理与合同事件；发运不能直接增加现场库存 |
| 完工、可用、移交、结算与清偿 | 各有必要条件；进度100%不能自动形成许可、接受或免债 |
| 暂停、终止、关闭 | 暂停可保留接续；终止不抹除实际事实；关闭需满足对应对象的责任条件 |

## 4. 配置、运行与比较身份

| 对象 | 含义 |
|---|---|
| ScenarioDefinition 情景 | 有稳定ID/版本的一组世界、政策及方法配置；不是一次运行 |
| ScenarioPortfolio 情景组合 | 围绕研究问题组织的情景版本与比较关系 |
| ContrastDefinition 比较定义 | 参与组别、基准、变化/控制、反馈范围、指标和估计目标 |
| Experiment 实验计划 | 固定情景/比较、重复与停止规则、输入和预算 |
| Execution Job 执行作业 | 显式启动计划的执行记录，不等于全部运行完成 |
| Run 运行 | 具有独立身份、初态、认知、随机及执行记录的一次世界实现 |
| Run Set 运行集合 | 有版本的实际运行成员清单，不由计划次数或情景卡合成 |
| Pairing 配对 | 经设计和实际元数据核对的重复对应关系，相同seed不自动保证有效 |
| Comparison Result 比较结果 | 固定指标、范围、时间、样本与方法版本下的正式统计输出 |
| ComparisonContext 比较上下文 | 前端引用同一正式比较、运行集合和结果的载体 |
| MapViewSelection 地图查看选择 | 选看哪一次运行/哪一对、图层和对象；默认不改变分析全集 |

政策来源、参数/方法与配置内容需保留可追溯版本。这里的版本是复现实验所必需的数据身份，不是文档中的迭代叙述。

## 5. 时间、数据与证据状态

- **业务时间**决定政策、任务、工程和资金何时发生；**墙钟时间**是程序运行耗时；**查看位置**是正在浏览的已保存状态；三者不能互相替代。
- **Snapshot**支持查看某一状态；**Checkpoint**只有包含规定的完整执行信息才支持恢复。各运行的commit_seq仅在各自命名空间内表示顺序。
- **存量**按时点读取，**流量**按期间累计，**比率**明确分子与分母。同名指标还需核对单位、币种、对象与地域归属。
- **零值**是已知结果；**缺失/未知**是没有可确认值；**不适用**表示语义不成立；**未支持**表示方法或接口不可用。不得统一补0。
- **真实/合成**描述数据来源；**假设/估计/已核验**描述证据性质；**草案/选定**描述配置状态；**未实现/可用**描述软件能力；**待验证/有证据**描述实际检查。这些状态相互独立。
- **运行执行状态、指标分析可用性和本次读取状态**是三条轴。部分中断历史可按指标规则使用，读取成功也不等于运行完整；业务正常放弃允许产生有效零新增。

## 6. 编号与规范语言

| 编号 | 查找位置 |
|---|---|
| SCOPE | 研究范围 |
| ARCH、WORLD | 世界运行 |
| OBJ及共同CHECK | 共同对象 |
| FLOW、CHECK-FLOW | 项目运行 |
| P01—P23 | 跨主体协作链索引 |
| OWN、BANK、ARCHITECT、ENGINEER、QS、GOV、CONTRACTOR、SUPPLIER | 对应角色的行为与规则；A表示行为卡 |
| POL、INST | 政策量化、政策工具 |
| RUN | 运行与结果 |
| SKL | 技能架构 |
| TYPE | 工程类型与方案模板 |
| CHECK-UI | 前端交互验收 |
| D-01—D-12、W1—W5 | 模型决策与接口准备 |

“必须/不能”表达模型不变量或接口要求；“允许/可以”表达有条件支持；“候选/待选择”不构成默认配置。规则引用保持唯一，示例不能覆盖主定义。所有检查项在执行前都只是验收要求，是否通过由对应证据决定。
