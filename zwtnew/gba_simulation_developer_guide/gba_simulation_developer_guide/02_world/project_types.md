# 工程类型与交付模板

规范性质：目标开发契约。工程目录覆盖建筑（含超高层属性）、道路、桥梁等；可运行模板、具体参数和候选预算须按[模型选择](../07_experiments/model_decisions.md)确定并登记实现与验证证据。

[总入口](../README.md) · [研究边界](../01_overview/research_scope.md) · [共同对象](domain_objects.md) · [项目推进](../03_projects/project_lifecycle.md) · [待定选择](../07_experiments/model_decisions.md)

工程模板须绑定[输入输出契约](../06_engineering/interface_contracts.md)中的 MethodRef 与输入输出schema，并由[系统接口](../06_engineering/system_interfaces.md)调用。模板目录、计算方法、方法返回、正式工作完成和用途允许分别校验；不能只填写一个方法名称就登记为支持。

## 1. 规范用途与主规则归属

本文件统一维护工程对象目录、分类维度、有限建造方案及模板适用域，回答“这个范围属于什么工程，可以使用哪些有依据的方法”。它不重新定义八类角色行为，也不维护另一套正式项目、工程量或资金状态。

| 内容 | 唯一维护位置 |
|---|---|
| 工程目录、方案范围、模板字段和支持状态 | 本文 |
| 项目／区段／工作包身份、范围、地点和归集关系 | [共同对象](domain_objects.md) |
| 启动条件、任务责任绑定、依赖与整体交付 | [项目运行](../03_projects/project_lifecycle.md)；[协作链](../03_projects/collaboration_flow.md)只索引交接 |
| 主体接单、编制、判断、投入与异常处理 | [角色规范总入口](../README.md) |

| 合成示例、统计和验证 | [贯通场景](../07_experiments/reference_scenarios.md)、[运行结果](../07_experiments/run_and_results.md) |

## 2. 工程对象与分类维度

**TYPE-001｜工程对象、用途与业主目标分别记录。** 以下是仿真目录，不是法定工程分类，也不代表全部类型已能计算。分类落在有实际范围的工程对象上；总项目可由多种对象组成。

| 对象目录 | 可进一步细分的范围 | 模板需要的代表性描述 |
|---|---|---|
| `building` 房屋建筑 | 居住；办公／商业／旅宿；教育／医疗／照护；工业／物流建筑 | 具体用途、面积、楼层、空间与功能要求；混合用途记录各自范围 |
| `road` 道路 | 城市道路、公路、园区道路等 | 路线／区段、长度、宽度、路基路面、排水与交通设施 |
| `bridge` 桥梁 | 城市桥梁、高架、跨江跨海桥梁等 | 跨径组合、桥面与基础、结构体系、接口及架设条件 |
| `tunnel` 隧道 | 道路隧道、铁路隧道等 | 区段、长度、断面、地质信息、支护及机电要求 |
| 专项扩展 | 港口、水务、能源以及轨道等专项设施 | 启用前创建明确子类、单位与方法，不能用一个通用“其他”方法计算 |

房屋用途的一级分组只供检索；酒店、办公、学校、医院等仍有独立子类。工业厂房的建筑工程不自动覆盖全部生产工艺设备。综合交通项目、轨道交通项目或综合开发区通过子工程组合表达，不复制道路、桥梁等实物。三类 Owner 目标仍为投资收益、自用需求、公共服务；用途不自动决定公私身份、融资或采购方式。

**TYPE-002｜高度、结构、材料和施工方式不混成一列。** 最小分类维度如下；输入值、单位、证据及未知状态沿用 [共同对象](domain_objects.md)。

| 维度 | 示例与约束 |
|---|---|
| 工程对象与功能用途 | 建筑／办公，桥梁／道路通行；明确该用途属于建筑还是服务功能 |
| 建设任务 | 新建、扩建、既有工程改造；每种任务声明保留范围及接口，纳入的任务范围按 D-06 选择 |
| 几何与规模 | 建筑高度、层数、面积；道路长度、宽度；桥梁跨度；隧道断面与长度，各按具名单位记录 |
| 材料与结构体系 | 混凝土、钢、组合材料及适用结构方案；材料名称不等于完整结构体系或建造方式 |
| 部位与工序方法 | 现场浇筑、构件预制与安装、三维模块制造安装等；绑定具体部位／工作范围 |
| 区位及现场条件 | 区段位置、地质资料、运输与作业条件及可见证据，不由角色随意补成已知事实 |
| 组织与采购安排 | 委任、设计整合、采购合同和联合参与安排；不以某一种技术自动决定合同模式 |

“超高层办公楼”属于建筑对象、办公用途，另记高度等属性。超高层标签如用于规则判断，须引用适用地区、日期及分类依据；不在这里设一个全湾区统一法定阈值。超高层模板需要自身的结构、机电、垂直运输、施工设备等适用条件和方法，普通建筑乘一个复杂度系数不能据此宣称已支持超高层。

## 3. 总项目、区段与方法适用范围

**TYPE-003｜模板绑定有边界的工程范围。** 采用 [共同对象](domain_objects.md) 的“总项目 → 子工程／区段 → 工作包”引用；简单项目可以直接包含工作包，不为满足展示层级虚构子项目、法人或合同。范围归属和功能依赖分别定义，父项目只按明确口径汇总，不能把父概算与全部子项实际成本相加。

一条跨区通道可以含道路、桥梁、隧道与附属建筑，并分别引用模板。同一实物只归集一次；跨边界的连续结构可关联多个所在地及事项，不为画行政分界而虚构重复结构或强行切断物理连续性。共享临建、设备和管理服务有明确归属或分摊，不能每个区段各计一份完整投入。各区段和跨区接口怎样推进，由 [项目运行](../03_projects/project_lifecycle.md) 维护。

## 4. 有限方案库

**TYPE-004｜方案由支持的部位与工序组合生成。** 以下为方案库的适用方向，不直接构成可执行技术方案；实际候选必须满足该模板的输入、范围与方法要求。

| 模板范围 | 有限候选可以比较什么 | 不能自动推出什么 |
|---|---|---|
| 房屋建筑 | 现场施工为主、预制构件装配为主、三维模块 MiC 为主的部位组合 | 三者不是严格互斥技术；不能凭项目标签推导全楼成本或工期 |
| 超高层适用的建筑模板 | 支持的结构与部位组合、分段施工、垂直运输和设备组织 | 高度增加不等于所有工程量等比例增加；普通模板或局部 MiC 不能代表全楼适用 |
| 道路 | 给定路线与场地信息下的路基处理、路面结构、排水和施工组织组合 | 沥青／混凝土是材料及路面体系选项，不独自构成全项目建造方案 |
| 桥梁 | 在支持的结构体系下比较现场浇筑、预制梁或节段运输架设等组合 | 梁桥、拱桥、斜拉桥等结构类别与施工方法分别判断，不能任意交叉组合 |
| 隧道 | 适用区段的开挖、支护、出土、机电和施工组织组合 | 不同地质与现场条件不能通用一个掘进率；方法不明时不能默认盾构或任何其他工法可行 |
| 专项工程 | 已登记子类内的设备、土建、安装和调试组合 | 未定义的专项内容不能靠“其他工程”系数补全 |

MiC 的三维模块可以使用不同材料体系；MiMEP 属于机电部位的集成预制方案，可与不同主体工程方式组合。DfMA 是面向制造装配的设计方法，BIM 是数字化表达与协作方式，不额外作为互斥的整项目建造类别。术语依据见第 9 节，不据此赋予任何方案必然优势。

**TYPE-005｜有限候选不等于强制产生可行方案。** 模板声明可选变量、有限值／取值边界、组合兼容性、候选与修订预算、终止条件和超范围结果。`design_profile_ref` 引用设计变量子配置，并与本文件工程模板版本明确关联。智能体可以选择受支持项、提出补查、申请有范围的新模板需求，或说明没有适用候选；不能生成无限几何细节或未经定义的工法并让核心默认为成功。

候选和修订上限由 D-07 选择；“最多两个初始候选＋一轮修订”仅为候选简化方案，不是默认值。模型调用预算、专业实际工作投入和业务工期分别记录；零候选、缺证、技术不适用与预算耗尽分别返回。候选形成只使用主体可见资料，隐含真实状态不能经筛选器泄露；正式提交沿 [共同对象](domain_objects.md) 的有权校验与版本检查处理。

## 5. 模板字段契约

**TYPE-006｜模板是有版本、适用域和方法引用的契约。** 下表定义字段语义；具体类型、配置和实现入口按[实现契约](../06_engineering/implementation_contracts.md)填写。仅有文档或模板名称不代表存在可加载配置。

| 字段组 | 必填内容 |
|---|---|
| 身份 | `profile_id/version`，工程对象与具体子类，适用建设任务；与设计变量子配置的绑定 |
| 适用域 | 用途／服务功能、规模条件、地区／日期条件、场地与证据要求、明确排除范围 |
| 输入 | 需求简报和范围版本、具名单位、必要观测／证据、可接受不确定性及缺项处理 |
| 方案变量 | 有限候选值或边界、相容／互斥关系、候选预算和修订规则；未选上限标待定 |
| 数量依据 | 从功能与方案到可核对工程量的 `method_ref`、范围和版本；不能把米、平方米、立方米与套混加 |
| 任务与资源 | 代表性工作包、工序及必要人机料、资源单位和共享约束；正式对象引用 [共同对象](domain_objects.md) |
| 专业职能 | 所需编制、整合、检查、计价、签署等任务的角色／能力条件；具体主体和授权按 [项目运行](../03_projects/project_lifecycle.md) 绑定 |
| 依赖与接口 | 许可适用性来源、方案／采购／制造／施工／检查的依赖模板、跨区接口及可并行范围 |
| 计算与失败 | 工程、质量、工期及成本方法引用；适用输入、错误／不支持／待补证结果与责任入口 |
| 交付功能 | 工作包完成、分段接收、必要测试与许可、整体可用条件；与需求供给记录的绑定 |
| 数据与依据 | 来源、假设、参数和不确定性；校准范围及证据版本，不把来源标题当具体参数证据 |
| 覆盖与验证 | 完整／局部范围、未覆盖余项、实现引用和验证记录；按第 7 节分别声明状态 |

相同功能范围比较候选时，固定需求、边界和评价口径，保留每个候选的范围／方法版本及剩余不确定性。一个候选采用的结构与成本意见不能拼接为另一候选的结果。模板更新只形成新版本，对在途项目的影响按已有变更、依赖和生效规则处理，不回写已发生事实。

## 6. 专业职能绑定

**TYPE-007｜按专业任务选择主体，不要求每个工程齐备八角色。** 八类角色各由一份规范维护；下表只指向应绑定的职能，不授予资格或项目权限。

| 工程范围 | 专业任务绑定方向 | 行为主定义 |
|---|---|---|
| 建筑及超高层建筑 | 建筑／空间任务由适用 Architect 编制；结构、机电、岩土等由相应 Engineer 承担；整合方按委任确定 | [Architect](../04_roles/architect.md)、[Engineer](../04_roles/engineer.md) |
| 道路、桥梁、隧道 | 对应专业 Engineer 编制受托工程方案；附属建筑或空间任务可另委任 Architect | [Engineer](../04_roles/engineer.md)、[Architect](../04_roles/architect.md) |
| 所有工程的量价与履约任务 | QS 按各自数量口径计价；Contractor 按任务能力组织施工；Supplier 按规格及生产／交付能力供货 | [QS](../04_roles/qs.md)、[Contractor](../04_roles/contractor.md)、[Supplier](../04_roles/supplier.md) |
| 项目目标、资金和法定事项 | Owner 决定权限内的目的与投资；Bank 按实际融资任务参与；Government 按区段／事项权限处理 | [Owner](../04_roles/owner.md)、[Bank](../04_roles/bank.md)、[Government](../04_roles/government.md) |

Engineer 角色不是无所不能的工程机构；每项专业方法和资格仍有适用范围。编制、独立检查、业主取舍和许可分别绑定；跨区联合团队也不自动补齐缺失权限。企业差异用工程对象／方法经验、目的地熟悉度、可核实资格、可见合作接口及真实资源表达，不设“某地区企业天然更先进”的固定加成。团队报价、工作量与方法结果需要各自依据。

## 7. 目录、方法、实现和验证分别标记

**TYPE-008｜支持情况至少分四个维度。** 不使用一个 `supported=true` 同时代替所有状态。

| 维度 | 需要说明 |
|---|---|
| 目录与设计范围 | 已登记什么类型、子类及范围；目录候选或选定实验对象的状态 |
| 方法定义 | 完整方法、局部方法或缺项；输入、数量转换、履约、质量及交付方法是否连通 |
| 代码实现 | 未实现／部分实现／已实现，附实际版本与实现位置；文档存在不能代填 |
| 验证证据 | 文档核对、离线行为检查、工程校准、独立预测或研究验证分别记录范围、数据和结果 |

目录登记不授予可运行状态；各模板只有满足方法、实现和验证要求后才能声明对应覆盖。F-GBA-01 是用途无关的合成局部接线基准，不证明住宅、超高层、道路或桥梁具备整项目方法。若实验只覆盖局部范围，应在输入与结果都声明余项；不能用局部构件成本自动外推完整项目。启用的工程类型、需求单位、方法与参数按 D-06/D-07/D-08 选择。

## 8. 模板验收场景

以下为开发验收预期，实际执行结果及覆盖范围另行登记。

| 编号 | 场景 | 应有结果 |
|---|---|---|
| CHECK-TYPE-001 | 同为办公建筑，一个具有超高层属性 | 用途保持办公，分别匹配方法适用域，不切换业主目标 |
| CHECK-TYPE-002 | 把建筑面积换算方法用于道路长度 | 报不支持／单位不符，不生成虚构工程量 |
| CHECK-TYPE-003 | 钢材体系与 MiC 同时出现 | 按材料、结构和部位方法独立核对，不能仅因标签并存而判互斥 |
| CHECK-TYPE-004 | 候选组合超出桥梁方法支持范围 | 保留缺项或不支持原因，不自动套建筑方法或默认通过 |
| CHECK-TYPE-005 | 道路方案由相应专业 Engineer 编制 | 按授权继续，不强制补一个无任务的 Architect；独立检查权限仍单独核对 |
| CHECK-TYPE-006 | 跨区通道部分区段已接收，关键连接未就绪 | 分段事实成立，整体功能按依赖检查，不直接发布全线可用 |
| CHECK-TYPE-007 | 同一共享临建设施供多个区段使用 | 真实投入只记一次，分配和父层汇总可追踪，不叠加两份成本 |
| CHECK-TYPE-008 | 通道包含道路与桥梁，统计总体产出 | 各工程量保留自身单位；整体服务另按功能方法计算，不把里程、面积直接相加 |
| CHECK-TYPE-009 | 只登记隧道类别但无对应计算方法 | 可保留提案与研究任务；依赖方法的执行不支持，不标成可运行模板 |
| CHECK-TYPE-010 | 候选均不适用或修订预算耗尽 | 返回相应结果并由有权主体调整／等待／退出，不强造可行方案 |
| CHECK-TYPE-011 | 跨区联合设计但缺少某项签署权限 | 保留未满足事项，联合参与本身不自动授予权限 |
| CHECK-TYPE-012 | 模板版本修订，旧方案已有评估与采购 | 逐项检查范围和依赖，保留历史，不默认全量失效或全部沿用 |

## 9. 术语与示例来源

以下资料用于工程术语与分对象／分区段方法的背景依据，不直接提供湾区通用工效、报价、超高层阈值或法定许可条件。

- [香港建造业议会：MiC 与 MiMEP](https://www.mic.cic.hk/en/AboutMiC)：MiC 为集成三维模块，MiMEP 面向机电集成预制；材料体系与制造装配方法需分开表达。
- [香港土木工程拓展署：跨既有铁路高架桥转体施工实践说明](https://www.cedd.gov.hk/filemanager/eng/content_22/Practice%20Notes%20on%20Horizontal%20Bridge%20Rotation%20Method%20for%20Viaduct%20Construction%20Across%20Existing%20Railway%20Lines_Final.pdf)：第 2.2 节列举预制与现场浇筑等桥梁施工路径及现场约束，不能只用房屋方案包概括桥梁。
