# CONTRACTOR-A06 核对动员与具体施工放行

只消费原所选任务、有效合同或独立准备授权、当前完整必要就绪要求和有权准备配置。准备目的不改施工目的，实际任务/动作/范围/窗口、原行动权限均一致。签约或选供应商不代就绪证据。

Evidence精确引用、双端同钟、非未来并按实际用途核有效窗：当前任务/门控/资源/许可及最低量依据按now，原设计发布/专业检查/现场/适用性/核验/ReadinessEvidence的签发依据按真实authored_at；现场及实际资源用于当前就绪另核now。无独立发生点的历史预留保历史，不以可获时间推造原发生。授权精确核原RoleAssignment.function_ref、角色、动作及完整scope，grant/function的Evidence按真实授权用途；其他basis保原类型、读权及原可获。

request_release逐必要要求核有权独立适用性、许可实际效力与动作范围、设计发布/专业检查/当前用途、实际现场交付/安全准入、资金/行动权限、原已完成前置，以及可用/已实际预留人机材料。空许可/设计输入保留未知；明确不适用也须独立原核验。输入精确非零最低量与实际已验可用量、原排他预留/时窗/完整占用账核对，不把报价、计划预留、到货未验或零投入当可用。实际物理池和原核心事件/分配身份排重，防止同输入跨要求重复满足。放行只是请求，核心再验并仅放行相关范围。

每份就绪核验绑定原任务/要求/范围/窗口、独立核验方职能、完整原来源内容摘要和读权/执行时点；未知不当通过，技术失败单独返回technical_error，未建模unsupported。任务前置图核循环，循环保留原要求及责任方；不放行对应任务，不扩大到全项目。

原适用性/核验记录可有合法较广scope，linked有权读取后须覆盖完整要求，原作者授权仍覆盖完整签发范围。适用性作者具原task/requirement/Evidence读权且输入不晚于签发；核验作者具task/requirement/applicability、完整原来源及嵌套Evidence读权和签发前可获，原来源Evidence在核验签发点逐用途核窗。当前完整资源/原核心分配/当前最低量重验保持。Known[Measured]外层只有state/value，实际可用量依据只读内部value.basis_ref；实际量须observed，formal拒synthetic，fixture显式合成不升级真实来源。执行和占用窗口均核双端同钟。

rectify_dependency允许未取得许可/设计时针对原必要缺项提出局部调查/澄清/隔离/整改/争议，责任未知保持unknown，不用缺证据推断法律禁止。resequence仅提同原有效授权内独立未完成工作包，原任务和义务保留，替代任务仍须各自核原放行；不从改序自动执行或解除循环。

三等待条件升v2，原/当前task/profile/mandate/requirement依据按各真实调用时间，原首门及当前完整新决策均用实际processor模块；native终态/独立解除循环证据仍当前observed且非synthetic。reader v3固定实际condition factory/history checker/processor/注册契约/source validator/schema对象与源码/runtime，终态使用同一实际checker；原v1条件/配置不自动迁移或重发放行。

completed不批准许可、不代专业核验、不创建放行/库存/实际产出；真实就绪/分配/专业生产者、跨动作投影、submit/query、原子核心门控和反馈仍待集成。本批编码未功能验收。

恢复reader v3在原组件身份与源码声明之外，显式保存各实际检查回调的callable_implementation运行时代码摘要，并沿原配置复核边界重新比较；源码文件摘要不能代替运行代码摘要。 此声明仅核代码；闭包、实例状态与partial参数仍由宿主明确配置和版本化。旧v1/v2配置不自动升级、重放或转换为已验证，新版本仍待集中业务验证。

本次就绪检查的原任务及全部替代任务依赖图按物理kind/id识别节点，并精确核每个物理任务只使用一个原ref版本；不同图分支和替代根不能混用同任务版本。改序不得借版本变化选回原任务或其直接前后置任务。循环保持原等待及责任证据，不删除依赖或自动放行；不同历史/当前调用仍可各用各自合法版本。
