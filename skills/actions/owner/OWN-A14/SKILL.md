# OWN-A14 持有资产、提出交易/运营及核对实际回款

核当前有权Owner、原core Asset实际权属/可用范围/完整权利、市场获知时点、交易/收款/业务历史；在有权具体ScopeChoice选择六分支。hold不自动产生租金。交易/运营必须明确场景机制、实际或外生对手及共同资金边界，未覆盖机制返回unsupported，不复制聚合买方完整预算到每个项目。自用/公共服务/收益目的分别保持，不强造租售市场或对手智能体。

offer_sale/offer_lease/transfer绑定具体原条款、权属/处置权/权利负担、适用条件及实际可用范围；租赁明确期间。预测金额保持known/unknown，known需原有来源的外部预测或明确场景假设，不代现实预测校准，更不能支用。operate仅原受支持服务计划、实际可用资产、任务和当前资金/许可条件；计划不宣称已履约、吸纳或产生收益，转售不新增物理存量。

处置负担只约束与本次目标有实际交集的原范围，部分交集仍需原权利人许可；锚点和WorkScope按物理身份识别，改版本不消除同一范围的负担，其他独立无交集范围不自动阻塞。授予本次选择权限仍核精确原版本与目标范围，不能由范围无交集推定本次有权处置。

reconcile_receipt只原实际收款：原CashReceipt/账户、真实收款法人/付款人、币种、时间、core事件/付款片段和完整分配历史；ReceiptAllocation支持分期以及一次收款覆盖多交易/资产，原物理分配不因报告展示重复。商业交易需原有效交易/义务；公共拨款或外生回款需显式core原依据/资金边界。不从使用率、预测、应收或竣工推导现金；款项限制保持，另一法人收款不转成本业主现金，借贷清偿仍交独立付款入口。限制可重叠，不叠加当新增扣款。

已有business沿原身份查询，不改变原内容重发。本批只编码和静态检查，功能验收待集中进行。真实来源生产者、跨动作投影兼容、市场/服务/资产/账本submit/query、一次到账与需求反馈尚待集成。

同business执行的profile_ref必须指向该执行的原资产版本、本组织、原范围及原business_key，再核原内容摘要及本次配置的业务内容。装配、动作和终态归档一致核对，不把另一资产的配置藏在可变化元数据中，也不把矛盾来源登记为待查询或终态成功。保留原合法资产版本更新，终态归档仍需真实query/native认证，不重放交易、运营或收款。
