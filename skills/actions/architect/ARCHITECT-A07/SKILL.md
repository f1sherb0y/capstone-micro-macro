# ARCHITECT-A07 成果提交、审查申请与用途放行

submit/request_review/release_for_use消费原Deliverable、完整依赖版本、真实TaskCompletion、拟用用途及合法非空接收者。原任务/内容摘要/已确认实际WorkFact分片、编制检查和独立作者/A07权限逐原身份核对，不能用文字“我已完成”填完成证据；完成编制与某用途检查通过分别判断。

三个分支都需独立原PublicationAuthority允许具体选择/用途/接收者。submit可无ReviewRequirement/ReleaseBasis；request_review须原非空ReviewRequirement且接收者具有对应受理职责，有限研究/估算可保留明确未决问题。提交和申请审查不生成allowed_use、approved、送达、合同接受、许可、事件或收费状态。

release_for_use额外要求独立放行权、完整原用途条件、非空ReleaseBasis及原核实记录/摘要/作者权限，真实记录须同成果版本、用途、条件代码和有效观察证据；机关许可只能由Government原记录、Owner用途决定只能由Owner原记录提供。阻塞该用途的开放/未知Issue不能被忽略，不把估算/报审版直接用于施工。

原依赖仍合法时不因出现新草稿失效，正式失效/用途限制逐原依据保留；已不适用所请求用途先补有效版本。全部原成果与依赖的未决Issue保留，提交不关闭问题。核心提交前仍重读权限与依赖，处理实际version_conflict/business_rejected，不以角色草稿伪造拒绝回执或放行事实。

原command_id/business_key/operation_id及规范payload摘要保持一致。已有提交、未知回执或业务拒绝沿原提交query；只有核心确认未提交才可同身份续试，不重复成果版本/计工/费用/现金。合法新返修使用有权新任务/增量及新命令，保留历史并按原条款另核责任和费用。

completed只交提交/审查/发布服务，提交与审查任务的必要写集须核心原子提交，后续通知投递独立处理。真实版本库/完成执行器/接收职能/发布权/检查与ReleaseBasis生产者、跨动作投影兼容、正式prepare/submit/read_receipt、原子必要写集/通知/用途后果及反馈仍待集成。CHECK-ARCHITECT-007/012/015/039/053–057待集中验收。
