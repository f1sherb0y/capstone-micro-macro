# ARCHITECT-A08 有范围审查与原作者回应

review/respond/propose_revision消费有效原ReviewRequest、指定Deliverable版本/内容摘要、收到的MethodResult/ReviewComment及原独立性模板，逐原作者/职能/权限/用途/范围/获知时点核对。review只在本主体原职责内给建筑专业意见，不替Owner取舍、Government许可、Engineer结论或Bank核验。

支持意见须原范围全部CheckSpec及明确适用Method的成功检查证据。缺结果、模型超时或未知passed保留未验证；空结果只能undetermined，部分有证且无阻塞可limited_support，原检查已确认失败为revise，原用途阻塞Issue仍开放时不得support。无必需方法或明确不支持保持unsupported，不能用成果编制完成或业主外观认可补技术通过。

独立性按原模板no_requirement/different_personnel/unrelated_organization_and_personnel核对，不从“Architect”角色推定独立。模板要求时必须完整当前IndependenceCheck和独立核验权限，绑定原作者/审查人员、组织和关联组织；同人或禁止组织关系不能给独立意见，缺关系保持缺口。

respond/propose_revision只针对实际收到原版本意见，只有原作者身份可回应；非实质变化的解释引用明确依据，实质改变内容必须propose_revision。修订保留原affected_ref与具体Question/ResponseRequirement，不修改对方原ReviewComment或其他专业结论。旧意见保留原版本，不自动套新版。

respond的内容由原ReviewRequest.author_response_ref指向独立ArchitectAuthorReviewResponse草稿提供，绑定己方actor/function/authority、指定target内容及选中收到comment的完整SHA。草稿须在收到意见后形成、当前有效且有明确basis；缺己方草稿保持needs_information。ReviewComment的旧response字段仅保留原记录，不能成为己方回应。己方草稿声明实质改变内容时仍走propose_revision及原具体问题，不在respond中修改成果。

completed只形成有范围专业意见/回应/修订请求，不形成allowed_use、全部专业通过、合同接受或行政决定。真实ReviewRequest/CheckSpec/专业方法执行/独立组织关系/评论和问题生产者、跨A07/A08投影兼容、正式submit/query、原子意见/问题/修订后果与反馈仍待集成。CHECK-ARCHITECT-008/016/045待集中测试；当前消费已保存有来源检查结果，不证明真实方法校准。
