# ENGINEER-A01 识别专业需求与经营机会

核对原 Opportunity、本组织 Capability、ResourceCalendar 与独立准备授权。专业和职能未知或超出声明范围先 clarify/needs_information，不填新资格，不把市场文字变成订单。能力记录的显式选择顺序允许 track/express_interest/prepare/clarify/decline，不改变其他组织或共享机会。

track 引用原有效 Trigger；express_interest 只返回原邀请人和已核对 Discipline，不发送消息、生成委任、接受字段、收入或投入。来源未确认不得启动准备；问题保持原范围、目标、研究用途、回应要求与授权接收人。

有限准备可在 organization/assessment_case scope 申请，不要求完整设计或正式项目。原 PreparationRequestProfile 与独立 Authority 核对机会、能力、组织职能、目的、当前剩余费用/工作额度与许可输入/接收人。成本/工时来自同版输入及工作模板的已保存估计，核对原作者独立权限与方法的地区/专业/职能/对象支持域。技术失败保留 technical_error/unsupported，不转换为商业 decline。

有工作模板时使用宿主 micro.capacity.fixed_location，按原工程人员/设备适用专业与真实性排重，并保留同一物理资源全部原占用。不得复制人员、丢弃旧复查或无声抢占；固定地点、同单位、单时钟和未来半开窗限制明确。无工作模板可保留未知工时提交受限申请，不执行、不占资源、不收费；预算仍需原估计与限额。

completed 只为机会回应或任务申请。真实机会/能力/估计来源、任务创建、资源登记、正式提交/查询和反馈仍待绑定。CHECK-ENGINEER-001/003 待最后集中验证。
