# ENGINEER-A07 专业成果提交、签署和用途发布

submit/sign/release_for_use三分支分别形成原专业成果/版本的草案。原本组织作者、有效委任、同版条款摘要、专业/用途及独立A07职能权限、PublicationAuthority逐项核对。requested_use不写allowed_use。编制TaskCompletion绑定同任务/成果摘要、实际已确认WorkFact投资分片与内部成本/正工作量、真实编制完成检查；编制检查不代表报告的专业结论通过，冲突报告本身可完成。投入排重，原时间/接收顺序核对，不追加消耗/费用。

submit允许签署/发布依据空，只原获授权recipient子集，recipient Agent与经办Actor分别校验。完整依赖/问题逐原版本读取；旧合法成果不因新草稿失效，依赖失效证据保持。原未解决Issue不关闭、不隐藏。

sign必须原SigningBasis和SigningVerification，绑定目标内容、委任、真实签署组织/Actor/职能、用途、专业范围、条件code及原记录摘要。权限、资格和需独立性时的原A03核验覆盖每个所签专业；每条原条件成功已核实且证据充分。签署保留报告冲突/限制，仅对原已签范围，不自动机关提交/送达/合同接受/用途许可，不借结构资格签其他专业。

release_for_use另外核原PublicationAuthority、全部required_release_codes及原ReleaseBasis/实际核实记录摘要/目标内容、用途/作者职能/时间/已核实证据，原用途中阻塞Issue不能放行。行政许可只GOV有权记录，业主用途决定只OWN记录，不把成功计算、提交或签署当许可。

原命令/business/operation/分支/payload摘要及完整历史核对；已提交/未知/拒绝先query，只有confirmed_uncommitted续办，不生成第二次工作/成果/费用。一次选择只输出该分支字段，本动作不写签署、送达、接受、许可或现金事实。
