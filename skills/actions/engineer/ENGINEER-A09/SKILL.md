# ENGINEER-A09 专业修改、调试与缺陷复查

propose_remedy/revise/reassess/request_test四分支按原Issue/有效Obligation/Contract/原专业成果及版本、独立A09职能权限和义务允许专业/用途/分支。费用争议不抹去有效工作义务，不据此自动停做或免费；原施工/试验/投入与成果历史保留。

propose_remedy为原有限EngineerTaskRequest，purpose仅remedy/investigation，绑定原事项/义务/成果、独立原申请Authority、原输入/交付要求/依赖与问题。无需伪造新Task，缺工作方法可null，未知工作量保持；当前未绑定整改估算方法时已知自由估值unsupported。请求不消耗资源、不记执行完成。

revise只本组织专业成果，其他作者成果转原作者/有权整合者。原有权Instruction或已授权缺陷义务、ChangeBasis及原拟改内容摘要逐版本核对。原参数目录、实际改变项及影响依赖核对，删除参数也算改动；不覆盖未授权专业。不直接改原记录，复用A05有限编制逻辑但以A09独立权限运行，沿原需求/profile/父option、保存参数域结果、相容规则、实际投入和委任版本/返修/成本上限核对，新版本草案不抹旧事实。

reassess只原实际任务/当前成果内容和已保存A09执行、原输入事实/范围/专业/时间/方法/证据；需要独立性时核原A03记录和真实作者/审查人员/组织关系。原实际投入/investment_key排重。合成接口码方法复算，缺结果/失败null、未知/冲突并存，假设与未覆盖保持。V1结果不能冒充V2，整改计划不能复查通过，本动作不关闭Issue或生成使用许可。

request_test只原问题/接收权与原专业适用test方法，申请不产生试验结果。调试成功、专业发布、合同接收及GOV许可分别有独立入口。当前数学有限参数与合成接口码方法不证明现实物理性能。
